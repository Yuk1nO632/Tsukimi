# 频道 UI、播放页与真实资料

更新日期：2026-10-24。

## 本轮目标

首页与播放页参考 B 站番剧频道的布局习惯，保留 Tsukimi 自己的品牌与细节。界面骨架现在确定，真实业务能力逐步补齐，不把当前数据或播放能力误当成全部完成。

- 首页：大幅插画横幅、主题缩略导航、频道快捷入口、六部真实番剧封面、分类与搜索、首播日历和个人片单。
- 详情：真实名称、原名、简介、标签、首播日期、Bangumi 评分与集数；每一集可进入独立播放页。
- 播放页：左侧视频区、右侧选集、来源状态、追番按钮、下方简介与相关片单；支持宽屏与全屏布局。

横幅是内置 imagegen 生成的原创品牌氛围插画，没有把它们当作真实动画的官方海报。真实番剧卡片使用 API 返回的封面。

## 为什么可以显示真实番剧

API 是程序之间请求和返回数据的接口。我们的同步脚本请求 Bangumi 的公开条目接口，例如：

```text
GET https://api.bgm.tv/v0/subjects/400602
```

服务返回 JSON，包含番剧名称、简介、图片地址、集数、标签等。程序把它转换为卡片和详情页需要的数据。

当前资料流：

```text
Bangumi 公开 API
  → 同步脚本读取资料与封面
  → 项目中的本地资料缓存
  → Next.js 页面显示真实番剧
```

六部片单：葬送的芙莉莲、迷宫饭、孤独摇滚！、紫罗兰永恒花园、摇曳露营△、夏日重现。各条目有原始 Bangumi 链接和数据更新时间。

当前搜索在这六部已同步条目中进行，还没有做任意番剧的联网搜索。以后由 FastAPI 承接外部资料调用、缓存和查询。

## 为什么有资料还不能看视频

番剧资料接口回答“这是什么番、叫什么、有多少集”。播放器还需要对应剧集的视频地址、可用格式和来源状态。两者可以来自不同服务。

本轮没有视频源，所以播放按钮和弹幕输入明确禁用；选集链接、上一集/下一集、宽屏、全屏、收藏和详情导航可操作。没有伪装播放成功，也没有编造播放量或本站热度。

## 启动与刷新资料

在 VS Code 的终端中：

```powershell
cd C:\Users\lx\Desktop\Tsukimi\project\frontend
npm.cmd run dev
```

打开 http://127.0.0.1:3000。更新资料运行 `npm.cmd run sync:catalog`；已有依赖和资料缓存无需每次重新下载。

同步脚本使用系统 PowerShell 网络配置。当前环境下 Node 直接连接 API 曾超时，而系统请求成功，因此选用系统请求作为本阶段的同步工具。封面和资料保存在项目里，普通浏览不依赖实时外部 API。

## 本轮验收

- 主题缩略图和前后切换按钮能更换横幅与主题文案。
- 名称搜索、标签分类、清空与空状态能正确工作。
- 卡片、详情和播放页之间导航时，收藏与顶部计数一致。
- 真实资料的集数用于选集，URL 指定集数会高亮；首尾集数限制上一集/下一集。
- 非法集数和不存在的条目返回 404；旧演示链接仍可打开。
- 播放页直接刷新可访问；当前收藏在完整刷新后仍会重置。
- 桌面与手机没有横向溢出；真实封面和品牌插画能够加载。

首播日历按条目的原始首播日期分类，不是当前新番更新排期。评分来自同步时的 Bangumi 数据，不是实时本站评分。

下一阶段在同一个正式项目里加入 FastAPI、SQLite 和会话，让收藏真正保存，再逐步接入可播放来源。
