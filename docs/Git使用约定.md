# Tsukimi Git 使用约定

## 一个工作区，一个仓库

Git 仓库位于 `C:\Users\lx\Desktop\Tsukimi\.git`，同时记录 `project/`、`experiments/` 和 `docs/`。正式应用放在 project，之后的功能直接在原应用上迭代，不按版本复制多份正式项目。

当前是本地仓库，远程 GitHub 仓库可之后配置。

## 我们怎样提交

- 一次提交记录一个能说明清楚的阶段：例如首页与详情、收藏接口、数据库保存。
- 提交前查看差异，完成对应验证；提交信息使用简短标题加详细正文。正文写明为什么改、具体改了什么、如何验证及仍存在的限制。按改动规模控制篇幅，说明必须真实写进 Git，而不只写在聊天回复里。
- `node_modules`、`.next`、`dist`、缓存、截图输出、`.env` 和数据库运行文件不提交。
- 后续由 AI 完成的一个阶段，在检查通过后提交；你自己在 VS Code 修改时，也可以按同样方式提交。
- 如果发现尚未提交的个人修改，先确认归属与内容，再整理提交，不覆盖已有工作。

## 在 VS Code 中查看

打开整个 Tsukimi 工作区，左侧“源代码管理”能看到改动。点开文件查看差异；提交记录可在相关历史视图或文件时间线中查看。

## 常用命令

在工作区根目录执行：

```powershell
git status
git diff
git log --oneline -8
```

`git diff` 显示尚未暂存的修改；`git diff --staged` 显示准备提交的修改。只暂存本次涉及的文件，再提交，不把尚未检查的文件顺手一起提交。

## 想回退时怎么做

先明确是“查看旧版”“恢复某个文件”，还是“撤销一个完整提交”，并检查当前是否有未保存的工作。

- 查看旧版本：在 VS Code 的差异或历史视图中比较，不需要修改当前文件。
- 撤销一个已提交阶段：通常使用 `git revert`，它会新增一条反向提交，原有历史保留。
- 恢复某个文件：先比较内容，确认当前修改已经保存，再从选定提交恢复该文件并提交。

需要实际回退时可以直接说明“撤销哪个阶段”或“恢复哪个文件”，我们先查看差异再执行。日常回退不依赖 `reset --hard` 或强制推送。

每次提交后可用 `git status` 确认状态，再用 `git log --oneline -3` 确认最新记录。
