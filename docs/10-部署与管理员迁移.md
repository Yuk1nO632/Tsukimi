# 部署与管理员迁移操作记录

## 已完成的服务器准备

用户实操并提供截图。腾讯云香港服务器使用 Ubuntu 24.04 x86_64，约 2 GB 内存、2 GB Swap、40 GB 磁盘。Python 3.12、Git、curl、venv、Node.js 24 和 npm 已安装。tsukimi 用户拥有 /opt/tsukimi，仓库通过 HTTPS 克隆，服务器前后端依赖安装与生产构建通过。

后端 .env 指向 /opt/tsukimi/data/tsukimi.db，允许来源为 https://tsukimi.cc 和 https://www.tsukimi.cc，Cookie Secure 已启用。数据库初始化完成，浏览器登录安排在 HTTPS 入口接通后。

## 单账号迁移工具

用户选择全新业务数据，单独保留 Megumi 管理员。工具导出账号 ID、用户名、昵称、密码哈希、角色和已有密保资料。服务器导入前备份数据库，事务内检查目标，原样重复导入可安全重试，目标已有不同账号或业务数据时停止。原会话和追番数据属于原数据库。

本机导出，在工作区根目录执行。

```powershell
.\project\backend\.venv\Scripts\python.exe project/backend/transfer_admin.py export --username Megumi --output .cache/megumi-admin.json
```

迁移文件含账号认证资料，通过文件传输发送到服务器。聊天中反馈成功提示和文件大小即可。该目录已在 .gitignore 中忽略。

服务器获得工具及迁移文件后，在后端目录执行。

```bash
.venv/bin/python transfer_admin.py import --input /home/tsukimi/megumi-admin.json
```

本机核对显示 Megumi 是管理员，当前密保问题数量为 0，部署登录后补设。工具测试覆盖导入后使用原密码登录、保留已有密保问题、单账号及空片单、导入前备份、重复操作，以及账号冲突和非法文件。100 项后端测试通过。实际管理员导出、传输和服务器导入仍由用户按步骤执行。
