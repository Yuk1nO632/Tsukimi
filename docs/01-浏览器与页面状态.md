# 实验 01：浏览器与页面状态

预计 30–60 分钟。目标是通过观察复习，不要求背语法或手写整页代码。

## 本轮三个文件

| 文件 | 职责 | 先找什么 |
| --- | --- | --- |
| `experiments/01-browser-basics/index.html` | 页面结构 | 标题、筛选按钮、卡片模板，以及 CSS、JS 的引用 |
| `experiments/01-browser-basics/styles.css` | 页面样式 | 颜色、间距、卡片布局，以及窄屏规则 |
| `experiments/01-browser-basics/app.js` | 数据和交互 | `animeList`、`favoriteIds`、`render` 和点击事件 |

## 1. 启动与访问

依照 README 启动，在浏览器访问 `http://127.0.0.1:5173`。

先解释地址：`http` 是协议，`127.0.0.1` 是本机回环地址，`5173` 是当前静态文件服务器监听的端口。

观察：终端持续运行时可以访问。结束后，已打开页面仍可交互，但再次刷新会无法加载。这可以帮助区分已经加载的页面与正在提供文件的服务器。

## 2. 看清三类文件的关系

按 F12 打开开发者工具，进入 Network（网络），刷新页面。

找到 HTML 文档、`styles.css`、`app.js`。若使用缓存导致状态显示 304，不是失败；可在开发者工具中勾选 Disable cache 后重试。

回答：浏览器分别拿到了什么？哪一项决定外观，哪一项让收藏按钮工作？这些静态文件请求和后面要学的业务 API 请求有什么共同点？

## 3. 收藏与筛选

1. 收藏任意一部番剧，观察按钮、上方计数和提示。
2. 收藏另一部，确认计数增加。
3. 切到“已收藏”，确认只显示刚才的条目。
4. 取消一个收藏；继续全部取消，观察空状态。
5. 在空状态中点击“浏览全部”，返回完整列表。

在 `app.js` 中找到保存收藏的 `favoriteIds`。此时交互发生在浏览器内，没有业务后端或数据库请求。

## 4. 刷新为什么会丢失收藏

先收藏一部，再刷新。预期：收藏计数归零，条目回到未收藏。

找到 `const favoriteIds = new Set()`：每次重新加载脚本，这份内存数据都会重新创建。这是本轮刻意保留的实验现象。

记住三个层次：

- 当前页面内存：本轮使用，重新加载后重置。
- 浏览器本地存储：可跨刷新保留，仍属于特定浏览器，不等于云同步。
- 服务端数据库：由后端持久保存，还需要身份或会话区分记录归属。

后面会先迁移 React，再接 FastAPI、SQLite 和会话，不急着在这一步添加持久化。

## 5. 做一次可见的小修改

任选一项：

- 修改 HTML 中的副标题，刷新观察变化。
- 修改 CSS 的 `--accent` 颜色，刷新观察变化。
- 修改 JavaScript 的一个演示条目标题，刷新观察变化。

你可以让 AI 帮忙改，但要先说明应该改哪类文件、为什么。修改后再恢复原样，练习确认改动范围。
