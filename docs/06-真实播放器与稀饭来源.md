## 其他番剧怎样匹配

打开其他番剧播放页，进入剧集后先等待自动匹配；若未唯一匹配，可直接确认候选，或在选集上方展开“更换来源 / 匹配有误？”输入别名搜索，核对结果中的季数、年份和集数，再选择对应作品。匹配完成时手动搜索收起；没有来源或播放失败时，画面中的“搜索 / 更换来源”按钮会滚动到搜索框并聚焦。

当前只预置芙莉莲这一组已核验关系，其余作品不自动猜季数。匹配结果写进网址中的 source 参数，刷新或分享这个网址可保留选择；2026-10-28 起，播放页确认后的来源编号也会按匿名会话记忆，详见指南 07 E。

搜索框调用的是稀饭动漫搜索，和首页筛选本地九部番剧资料是两个不同的入口。

## 三种 ID 与线路

| 标识 | 示例 | 含义 |
| --- | --- | --- |
| 本站条目 ID | bgm-400602 | 来自 Bangumi 的番剧资料 |
| 稀饭作品 ID | 26 | 稀饭站上的对应作品 |
| 稀饭剧集 ID | 329 | 该来源作品的第一集资源 |
| 线路 ID | 5 或 2 | 同一作品的主线或备用线路 |

网址示例：

```text
/watch/bgm-400602?episode=2&source=26&line=2
```

episode=2 是“第二集”，不等于上游剧集 ID。后端按 episode_number 和 main 类型查找，不按数组位置取集数，避免特别篇导致错位。匹配后，切集链接会保留 source 和 line；不存在的集数会给出提示，不用其他集数顶替。

## 两条数据流

```text
资料：Bangumi → 本地 catalog.json → 番名、封面、简介、集数

播放：
浏览器请求本站 /api/playback
  → FastAPI 读取记住的来源关系或自动匹配候选
  → 稀饭 API 返回选集与临时播放地址
  → FastAPI 返回播放 JSON
  → 浏览器的 video 元素直接请求来源 CDN
  → video 的事件更新 React 中的时间与按钮状态
```

FastAPI 不转发视频字节，SQLite 也不保存视频。后端提供的是来源搜索、集数匹配和临时地址解析。播放地址可能带有效期，不能当作永久地址保存；“重新加载来源”会重新向后端申请地址。

## video 与 React state 的关系

- video.play()、video.pause() 控制实际播放。
- 设置 video.currentTime 才会真正跳转到某个时间。
- loadedmetadata 事件表示已读到时长等信息。
- timeupdate 把当前时间同步到 React state，用来更新进度条和文字。
- pause、playing、waiting、error 等事件负责更新暂停、缓冲和错误显示。

仅修改一个叫 playing 的 React state 不会自动让视频开始播放。我们的控制按钮会调用 video 的方法，再由真实媒体事件确认界面状态。

MP4 可以直接交给 video；HLS 使用 .m3u8 播放列表。支持原生 HLS 的浏览器直接播放，其余支持 MSE 的浏览器使用 hls.js。切集、换线和卸载组件时会销毁旧 HLS 实例并停止旧视频。

## 播放页交互调整（2026-10-27）

- 视频始终占满播放器容器，工具栏浮在视频上方，不再挤占底部高度；全屏使用完整的浏览器全屏区域。视频保持原始比例，屏幕与视频比例不同产生的黑边属于正常留边，不拉伸或裁掉字幕。
- 正常播放时约 2.6 秒没有操作，自动隐藏进度条、工具栏、顶栏和鼠标；移动鼠标、触碰画面或键盘聚焦控制项可唤回。暂停、结束、缓冲和错误时保持可操作。触屏第一次触碰隐藏的画面只唤回控件。
- 点击画面播放 / 暂停，双击全屏；选中播放器后，空格或 K 播放 / 暂停，左右方向键跳转 5 秒，上下方向键调节音量，M 静音，F 全屏。输入框、下拉框和按钮沿用自身键盘操作，不抢占这些控件的按键。
- 来源搜索常驻选集上方，明确区分当前作品、播放线路、匹配状态和搜索候选；缺少来源可直接跳到检索框。搜索失败可重新提交，播放失败可重新连接。
- 整理播放页卡片、字号、间距和手机布局；播放器与页面均提供下一集入口。播放结束后可手动重播或进入下一集，尚未实现自动连播。
- 移除尚不可用的弹幕输入占位；播放器测试入口收进“播放帮助”，测试模式仍明确标注，不混入正片。
- “复制链接”只复制当前播放页网址，保留网址中的集数、来源与线路，不复制临时签名视频地址。首页顶栏搜索仍只筛选本地片库，与此处稀饭搜索不同。

代码复习时，注意区分 controlsVisible 这样的界面 state、video 的实际播放状态，以及 Fullscreen API 的真实全屏状态。隐藏工具栏只改变显示和鼠标交互，不停止视频；恢复进度仍未实现。

## 在 Network 看什么

| 请求 | 用途 |
| --- | --- |
| GET /api/sources/xifan/search?q=… | 搜索稀饭站作品 |
| GET /api/playback/{anime_id}?episode=… | 取得这一集的来源和临时播放地址 |
| play.xfvod.pro 的 MP4 请求 | 浏览器读取真实视频，可观察 Range 请求 |
| dl.playxf.top 的 m3u8 和分片请求 | HLS 播放和拖动时的实际视频流量 |

播放 JSON 的 format、source_anime_id、source_episode_id、line_id 用于区分不同角色。不要把临时视频 URL 或其中的签名复制进 Git。

## 独立测试短片

在播放器下方展开“播放帮助”，点击“试播测试短片”，使用的是本地 MDN CC0 花朵视频，约 5.055 秒。画面有“非番剧正片”标识，用来区分播放器本身是否正常和外部来源是否正常。

测试模式可以播放、暂停、拖动，再点击提示条的“返回番剧正片”或帮助中的“返回番剧来源”。测试短片不会作为缺失番剧资源的自动替代，也不会因选择第二集就变成所谓的第二集正片。

## 失败与边界

- 取得地址后仍需视频实际加载成功，才算播放链路通过。
- 视频网络或解码失败，显示重试；上游不可用、未匹配、缺集和不支持的地址分别给出提示。
- 手动重试会重新申请地址，切集时从零开始，并停止旧资源。
- 来源查询有超时；番剧详情缓存五分钟，临时播放地址不持久保存。
- 当前为稀饭 Next 单源，适配其已核对的 MP4/HLS CDN；不提供任意 URL 转发。
- 观看进度、自动续播、弹幕与下载尚未实现；刷新仍从头播放。
- 下一阶段再用现有 Cookie 和 SQLite 保存进度，不提前把本阶段标成已支持续播。

## 代码阅读顺序

1. frontend/app/watch/[id]/page.jsx：读取并检查 episode、source、line。
2. frontend/components/watch-studio.jsx：请求来源、切集、换线和测试模式。
3. frontend/components/media-player.jsx：video 事件和实际播放控制。
4. frontend/components/source-matcher.jsx：来源搜索和人工选择。
5. backend/playback.py：两个 HTTP 接口。
6. backend/xifan.py：公开来源 API、主剧集匹配、播放地址与错误转换。
7. catalog/xifan-bindings.json：仅保存已核对的默认作品关系，不含临时视频 URL。
