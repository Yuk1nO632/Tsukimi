## 第一版开发路线

完成基础实验后，以六个阶段推进；原先约 6 周的安排作为工作量参考，另留 1–2 周排错和试用。

1. **最小全栈闭环**：Next.js + FastAPI + SQLite，模拟番剧可以收藏，刷新后仍在。无需先打磨复杂界面。
2. **单源播放验证**：先用测试视频确认播放器，再验证一个候选来源的搜索、选集、播放和拖动；失败后最多换一个候选，仍不通过就记录阻碍、重新评估来源，暂停扩展功能。
3. **番剧资料**：默认研究 Bangumi API，完成搜索和详情；资料与视频来源分开封装，第一版允许手动确认两者关联。
4. **收藏与记录**：想看、在看、看完、取消收藏、最近观看；沿用匿名会话，暂不做账号与跨设备同步。
5. **播放与续播**：原生 video，HLS 按兼容性使用原生播放或 hls.js；支持选集、倍速、全屏，每 10 秒及暂停、切集时保存进度，失效播放地址重新获取。
6. **自用部署与试用**：沿用课程的 Linux、Nginx、systemd 路线；公网部署时配置 HTTPS 和站点访问密码，练习日志、重启、数据库备份与恢复，再实际使用一周。

第一版主流程：搜索 → 详情 → 收藏 → 选集播放 → 保存进度 → 继续观看。

## 第一版边界

- 主要验证 Windows Chrome、Edge，先完成桌面体验，再补基础手机布局。
- 后端负责资料、来源适配、收藏和进度；SQLite 不存视频文件。
- 默认由浏览器直接访问视频来源；若必须转发视频，先重新评估成本和复杂度。
- 资料中没有可匹配的播放来源时，仍可查看和收藏，并提示暂不可播放。
- 匿名会话对应浏览器，清除 Cookie 或更换浏览器后不保证找回原记录。
- 多人账号、多源规则、弹幕、下载、BT、超分辨率不进入第一版。
- 测试视频只用于验证播放器，不能替代真实来源验收。

## 每次学习的做法

1. 用自己的话回忆本次概念，不确定的地方才回看课件。
2. 一次只做一个能观察结果的小任务；AI 可协助生成代码和排错。
3. 操作后记录实际结果，说明页面、请求、后端与数据库各自发生了什么。
4. 完成一个阶段后保存 Git 版本；不会解释或尚未亲自验证的内容保留为待复习。
