## A 观看进度与继续观看

### 先观察结果

1. 按 README 启动后端和前端，进入一部番剧的正式播放页。
2. 播放一段，拖动到一个容易记住的位置，再暂停。播放器下方应显示进度已保存。
3. 刷新页面，确认恢复到同一集和附近的秒数。浏览器可能要求点击一次才能有声播放。
4. 打开首页或我的追番，点击继续观看卡片。详情页也有相应入口。
5. 切到另一集并播放，再回片单，确认记录的集数随之变化。
6. 重启后端，用相同浏览器和地址再次进入，确认记录仍可读取。

每部番剧保留最近观看的一集及其位置。自然播放到结束后，该集记录标记已结束，继续观看区展示尚未结束的记录。片单的想看、在看、看完状态由你自己选择。

### 数据经过哪里

```text
video 的 timeupdate、pause、seeked、ended
    ↓
MediaPlayer 报告当前秒数和总时长
    ↓
useWatchProgress 合并保存请求
    ↓
PUT /api/progress/番剧ID
    ↓
FastAPI 根据 Cookie 确定数据归属
    ↓
SQLite 的 watch_progress
    ↓
JSON 确认保存结果，React 更新保存提示
```

播放时约每 10 秒保存，暂停、拖动、切集和离开页面时也会尝试保存。首页预览及播放帮助里的测试短片独立处理，正式观看回调写入番剧记录。

视频临时地址会重新解析。数据库保存番剧、集数、秒数、时长、来源编号和线路编号。

浏览器异常退出时，最近一次尚未成功提交的位置可能丢失。普通网络失败保留待重试请求，在网络恢复或点击重试时再次发送。当前标签页的待重试请求暂存在 sessionStorage，关闭标签页会结束这份临时缓存。

### revision 和 operation_id

两台设备都读到了版本 3。设备 A 先保存，数据库变成版本 4。设备 B 仍携带版本 3 保存时，后端返回 409，并带上当前记录。

页面提供使用云端进度、以本机进度继续两种选择。后者是在你确认后，按最新版本重新提交本机位置，因此也支持主动回退和重看。

operation_id 识别同一次保存。网络断开后重复发送同一请求，后端返回已经保存的结果，避免把重试当作另一份新进度。

### 代码阅读顺序

- `project/frontend/components/media-player.jsx` 的事件回调和 initialPosition。
- `project/frontend/lib/use-watch-progress.js` 的读取、保存队列、重试和冲突。
- `project/backend/progress.py` 的字段校验、身份校验和版本比较。
- `project/backend/database.py` 的 watch_progress 表和查询。
- `project/frontend/components/continue-watching.jsx` 的卡片与播放链接。

## B 邮箱账号与跨设备同步

### 数据归属

```text
电脑 Cookie → 电脑登录会话 ─┐
                          ├→ 同一个账号的数据归属 → 片单、进度、来源选择
手机 Cookie → 手机登录会话 ─┘
```

Cookie 中是随机会话凭证，数据库 sessions 保存其哈希和 owner_id。users 保存账号资料与 Argon2 密码哈希。owned_favorites、owned_source_bindings 和 watch_progress 按 owner_id 查询。

后端从已验证的会话确定数据归属。前端还随写请求提交当前会话的 scope，避免切换账号后，旧页面延迟发出的保存写入新的身份。

首次升级旧数据库时，自动生成同目录的 `tsukimi.pre-accounts.db`，向新表复制旧记录并记录迁移标记。原表保留用于核对。回退代码前先保留当前数据库，同时确认需要使用哪个数据库版本。

### 本机注册与导入

这台机器已创建被 Git 忽略的 `project/backend/.env`，启用本地开发邮箱。重启后端后生效。

在另一台机器复习时，可先在后端目录复制配置并安装依赖。

```powershell
cd C:\Users\lx\Desktop\Tsukimi\project\backend
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

已有 .env 时先检查内容，再补充需要的配置。

1. 在匿名状态收藏番剧并观看一段，打开顶部账号入口。
2. 选择注册，填写邮箱、昵称、密码，点击发送验证码。密码为 10–128 个字符。
3. 在另一个 VS Code PowerShell 终端读取开发邮箱。

```powershell
cd C:\Users\lx\Desktop\Tsukimi\project\backend
Get-Content .\data\dev-mail.jsonl -Tail 1
```

4. 将该条记录的 code 填入页面，完成注册。
5. 页面提示发现当前浏览器的匿名记录时，选择导入或使用账号记录。
6. 导入补充账号中缺少的记录，重复条目保留账号数据。重复提交也可安全处理。

开发邮箱把邮件写入本机文件，需要显式设置 `TSUKIMI_ENV=development` 和 `TSUKIMI_MAIL_MODE=file`，服务保持绑定 127.0.0.1。验证码文件和 .env 由 Git 忽略。

### 两个浏览器模拟两台设备

1. 在 Edge 注册并导入记录，在 Chrome 用相同邮箱密码登录。
2. 打开我的追番，确认共享片单。
3. 在一个浏览器播放并暂停，在另一个浏览器进入继续观看，确认恢复位置。
4. 两端同时打开同一作品，交替拖动和暂停，观察冲突提示，再选择保留的位置。
5. 在一个浏览器退出，确认另一个仍可访问该账号。
6. 用另一个邮箱注册第二个账号，确认片单和进度隔离。

打开片单或返回窗口时读取记录。正式播放页返回窗口时检查远端版本，其他设备已有新进度时提示确认。

### 找回和修改密码

找回密码填写已验证的邮箱，申请验证码，再设置新密码。本地开发邮箱也使用上面的命令读取。重置成功后，所有设备的旧会话失效，用新密码重新登录。

账号页提供修改密码，需要验证当前密码，成功后重新登录。

验证码 6 位、有效期 5 分钟、同一用途发送间隔 60 秒、最多尝试 5 次。发送还有邮箱及来源 IP 频率限制，注册和重置按用途隔离。数据库保存带服务端密钥的校验值，成功使用后作废。登录失败及验证码尝试次数持久化到 SQLite。

### 代码阅读顺序

- `project/backend/sessions.py` 的 Cookie、会话哈希和 owner_id。
- `project/backend/accounts.py` 的注册、密码校验、验证码和导入事务。
- `project/frontend/components/account-provider.jsx` 的登录状态与身份切换。
- `project/frontend/components/account-panel.jsx` 的表单和反馈。

## C 后续接入腾讯云 SES

真实邮件待开通后联调。本轮使用测试替身核对 SDK 请求参数，浏览器验收使用本地开发邮箱。

开通邮件推送，验证自己能管理的发信域名，配置 SPF、DKIM、DMARC 等记录，创建发件地址和注册、重置两份模板。模板使用 `{{code}}` 和 `{{minutes}}` 变量，按控制台要求完成审核。

在后端 .env 中填写配置。

```dotenv
TSUKIMI_ENV=production
TSUKIMI_MAIL_MODE=ses
TSUKIMI_SES_REGION=ap-hongkong
TSUKIMI_MAIL_FROM=Tsukimi <noreply@mail.your-domain.example>
TSUKIMI_SES_TEMPLATE_REGISTER=你的注册模板数字ID
TSUKIMI_SES_TEMPLATE_RESET=你的密码重置模板数字ID
TENCENTCLOUD_SECRET_ID=邮件发送子账号密钥ID
TENCENTCLOUD_SECRET_KEY=邮件发送子账号密钥
TSUKIMI_ALLOWED_ORIGINS=https://你的网站域名
TSUKIMI_COOKIE_SECURE=1
```

服务端使用腾讯云 Python SDK 调用 SendEmail。创建仅授予所需邮件发送权限的子账号凭证，将配置保存在服务端。

真实投递验收覆盖 QQ、163、Gmail 等目标邮箱，确认有效期、重发、过期、垃圾箱、失败反馈及香港服务器连接。业务限流和云服务配额同时生效。当前按连接来源 IP 计数，部署反向代理时需结合可信代理配置验证限流行为。
